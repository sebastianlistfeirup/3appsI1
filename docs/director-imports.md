# Director import and portability profile

The local editor accepts its schema-v1 JSON or hashed ZIP package, original PNG/JPEG stills, MP4/WebM clips, WAV/MP3/M4A/OGG/WebM audio, and a bounded static GLB 2.0 subset. File pickers never fetch a remote URL. Failed imports leave the current document and timeline intact; the error appears in the active dialog. A successful project replacement remains available in Undo for the current browser session.

## Static GLB models

The GLB importer checks file/chunk lengths before loading Three.js resources. Limits are 50 MiB per file, 2 MiB JSON metadata, 64 MiB decoded accessor allocation, 100,000 triangles including node instances, 64 meshes, 256 nodes, depth 64 and 500,000 imported triangles per scene. It checks view/accessor byte bounds and alignment, attributes and index ranges, finite vertices/transforms, node cycles and repeated parents. Models must contain a default scene and embedded binary geometry. Original 12-triangle fixtures include `fixtures/director-relay.glb` plus generated PNG/JPEG crates, with their reproducible source in `fixtures/director-textured-fixture.py`.

The GLB profile supports static geometry, material colors and embedded static PNG/JPEG textures up to 2048×2048. It permits at most eight image payloads and sixteen texture/sampler descriptors per model, with at most 64 MiB of declared RGBA allocation per model and 128 MiB across retained scene assets. Every texture descriptor is charged, so multiple sampler variants cannot bypass the bound. PNG chunk bounds/checksums and animation markers, image headers, MIME, sampler values, UV channels and material references are checked before browser decoding. PNG data must also pass actual bounded streaming zlib decompression, because browsers differ in their willingness to accept partial damaged images. Real browser decoding and matching dimensions are then required; loader failures are fatal rather than silently producing an untextured model. External resources, extensions/compression, APNG animation, skeletal rigs, sparse accessors and morph targets are explicitly rejected. The GLTFLoader's resource manager permits only the local blob URLs generated for already validated embedded images. Model instances share geometry/texture resources within one rendered scene, clone tintable materials, and explicitly release geometry, textures and ImageBitmaps on disposal. The allocation budget measures base RGBA image memory; GPU driver overhead and mipmaps are additional. Imported source, declared rights, SHA-256, bytes and triangle counts travel with immutable scene versions. Old shot frames and scene versions remain unchanged when a model is moved or recolored. Removing the final reference to a model releases its draft allocation budget; immutable previous scenes retain their own asset snapshot and Undo restores the draft.

## Validation and browser fallback

Image dimensions are checked from PNG/JPEG headers before decoding, with a maximum 8192 pixels per side and 32 megapixels. File signatures must match selected media MIME types, and browser decoding must successfully determine a bounded duration. ZIP import checks file names, counts, expansion limits, project schema and hashes; embedded GLB geometry is revalidated before acceptance. Unknown schemas and bad hashes never replace a good document.

The default app creates five actual frames. If WebGL is absent, the same scene can be edited in a 2D floor plan and captured to real 1280×720 JPEG frames with a visible **2D-PLAN** label. Saved shot metadata records `frameMode: plan`; 3D camera frames use `frameMode: 3d`. The timeline, storyboard, JSON/ZIP/PDF and local MP4 remain usable in the 2D path. This is floor-plan review, not a substitute perspective render.

The local persistence profile uses IndexedDB and browser storage quotas. Large embedded projects can exceed a device's quota; the editor preserves the in-memory document, shows the storage error and offers export. Cloud synchronization and account isolation are disconnected.
